Many Rust symbols are not defined as single UEB cells. Symbols such as ->, =>, @, $, .., ..=, and the raw/byte string prefixes r"…" and b"…" are either represented by multi-cell indicators, arrows, or transcriber-defined symbols in the Guidelines for Technical Material. Do not assume a single-cell equivalent. Consult the GTM for their exact transcriptions.

Notes

This list is not exhaustive. It covers the symbols most commonly encountered when reading Rust code and includes only transcriptions that could be verified against UEB sources: the Monarch UEB Technical Cheat Sheet, the UEB Quick Reference Chart, and UEB math lesson 6.3. For a complete and authoritative list of UEB symbols, including arrows, grouping indicators, and technical notation, refer to the Unified English Braille Guidelines for Technical Material (ICEB).
Grade 1 (uncontracted) is recommended for code. The UEB guidelines for technical material call for uncontracted Braille when transcribing displayed computer code — every character maps to one cell, so nothing is abbreviated away.
Context disambiguates. Several symbols share a cell across meanings — & (borrow vs. bitwise AND), * (multiply vs. deref), # (attribute vs. number sign), ? (question mark vs. error propagation). The surrounding code tells you which one applies.

a–j base · k–t = a–j + dot 3 · u,v,x,y,z = k,l,m,n,o + dot 6 · w is the exception.
