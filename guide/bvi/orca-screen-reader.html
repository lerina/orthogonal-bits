🐧 Native MATE Terminal Shortcuts (Moves the Window)

These commands scroll the terminal view itself. Orca will automatically read the new lines as they scroll into view.

  • Shift + PageUp: Scroll one page up.
  • Shift + PageDown: Scroll one page down.
  • Shift + Home: Scroll to the absolute top of the history.
  • Shift + End: Scroll back to the active prompt.

🦉 Orca Laptop Mode Flat Review (Reads Visible Text)

These commands let you review text currently visible on the screen without moving your terminal cursor. Remember that CapsLock is your Orca modifier key.

  • CapsLock + Ctrl + U: Jump to the very top line.
  • CapsLock + U: Move up one line.
  • CapsLock + I: Read current line.
  • CapsLock + O: Move down one line.
  • CapsLock + J: Move to the previous word.
  • CapsLock + K: Read current word.
  • CapsLock + L: Move to the next word.

⌨️ Command Line Editing Shortcuts

Use these standard Linux shortcuts to navigate the line you are currently typing:

  • Ctrl + A: Move cursor to the start of the line.
  • Ctrl + E: Move cursor to the end of the line.
  • Alt + B: Move cursor back one word.
  • Alt + F: Move cursor forward one word.

1. Orca Is Not One Navigation System — It Is Three

The single biggest source of confusion for anyone new to Orca is treating it as a single unified cursor. It isn't. Orca layers three separate cursors on top of each other, each controlling something different, each with its own keys, and each suited to a different kind of task.

The three layers are:

  1. The System Caret — the real, blinking text‑insertion point used by the focused application.
  2. The Accessibility Focus — which UI element (button, menu item, list entry, checkbox) currently has keyboard focus.
  3. The Flat Review Cursor — a virtual, Orca‑only cursor for reading the screen when nothing else works.

Once you can name which of the three you are currently using, Orca stops feeling random. Almost every "why is it reading the wrong thing" moment traces back to a mismatch between these layers.

The rule to memorize: "Orca is three cursors layered together: Caret writes, Focus clicks, Review looks."

2. Layer 1 — The System Caret

This is the actual text cursor inside whatever application has focus: a terminal, Helix, a Firefox text field.

What it controls:

  • The text insertion point
  • Where typing actually lands
  • The real editing position in the document or buffer

How to move it:

  • Arrow keys
  • Ctrl + Arrow keys (by word)
  • Home / End
  • Page Up / Page Down

Orca automatically speaks whatever the caret passes over — characters, words, or full lines, depending on your verbosity settings. This is the mode you live in while writing Rust code in Helix or typing commands in the terminal.

Think of this as: Editing mode.

3. Layer 2 — The Accessibility Focus

This is the layer that AT‑SPI2 exposes directly. When you Tab between a button, a menu, and a list in a GTK application — which is how essentially every MATE application, including Caja and MATE Terminal's dialogs, is built — you are moving the Accessibility Focus, not the caret.

What it controls:

  • Which interface element is currently active
  • What responds when you press Enter or Space

How to move it:

  • Tab / Shift + Tab
  • Arrow keys inside menus and lists

Key Orca commands on this layer:

  • CapsLock + Enter — Speak the currently focused object
  • CapsLock + / — Speak the window title
  • CapsLock + End — Read the status bar

Think of this as: Interface navigation mode.

This is the layer you're in constantly while using Caja's file pane, Firefox's toolbar, or any settings dialog.

4. Layer 3 — The Flat Review Cursor

Flat Review is Orca's own virtual cursor. It does not exist inside the application at all — it is a screen‑reader‑side representation of everything currently rendered, and it lets you inspect content that has no real caret and no accessible focus, such as unusual terminal output or a broken or partially‑accessible UI element.

What it controls:

  • A temporary, read‑only exploration point
  • Nothing in the application itself moves when you use it

Toggle Flat Review: CapsLock + P

Move within Flat Review, using the 3×3 grid:

  • CapsLock + U — Previous line
  • CapsLock + I — Current line
  • CapsLock + O — Next line
  • CapsLock + J — Previous word
  • CapsLock + K — Current word
  • CapsLock + L — Next word
  • CapsLock + M — Previous character
  • CapsLock + Comma — Current character
  • CapsLock + Period — Next character
  • CapsLock + Ctrl + U — Jump to the very top line.

Think of this as: Screen inspection mode.

Why Flat Review Trips People Up

Flat Review does not move the real caret. If you use Flat Review to examine a line of Rust code and then start typing, your keystrokes land wherever the real caret was left — not at the position you were just reading. This is the classic Orca trap: you're looking at one place but writing into another.

The fix — syncing the cursors:

  1. Use Flat Review to find the position you want to edit.
  2. Press CapsLock + 7 — this performs a "left click" at the review position, moving the real caret there.
  3. Turn Flat Review off with CapsLock + P.
  4. Continue editing normally.

5. How Often You Should Actually Use Each Layer

Experienced Orca users follow a rough proportion:

  • ~90% of the time — Layer 1, System Caret. Arrow keys, Ctrl+Arrow, Home, End. This is normal Rust editing and terminal work.
  • ~9% of the time — Layer 2, Accessibility Focus. Tab, Shift+Tab, arrow keys in menus — normal UI navigation in Caja, Firefox, and dialogs.
  • ~1% of the time — Layer 3, Flat Review. Only when the UI is broken, Orca has lost context, or you're inspecting unusual terminal output.

If you find yourself reaching for Flat Review constantly during ordinary coding, that's a signal something upstream is misconfigured — not a signal that Flat Review is the normal tool for the job.

Memory trick:
Caret = Write
Focus = Click
Review = Look

6. AT‑SPI2 2.56.2: What It Actually Does For You

AT‑SPI2 (Assistive Technology Service Provider Interface) is the layer sitting between GTK/MATE applications and Orca. It is not something you interact with directly, but understanding its role explains a lot of Orca's behavior on this system:

  • AT‑SPI2 exposes UI structure, not raw pixels. This is why Layer 2 (Accessibility Focus) works reliably in GTK apps like Caja and MATE Terminal's menus — the application is actively reporting its widget tree, roles, and states.
  • Terminal content is different. The text inside a terminal emulator's scrollback isn't a widget tree — it's a stream of characters. This is part of why terminal output sometimes needs Flat Review rather than normal focus navigation: there may be no discrete "accessible object" for a given line of shell output, only text content.
  • If an application does not implement AT‑SPI2 properly (poorly‑behaved Java apps, some Electron apps, certain custom‑rendered UI), Orca has nothing to read from Layer 1 or Layer 2, and Flat Review becomes the only option. On a stock MATE + GTK system like this one, this is rare, but worth recognizing immediately if it happens: if Tab and arrow keys produce silence in an application, stop trying Layer 2 and switch straight to Flat Review.

Practical takeaway: on this system, GTK‑based MATE applications (Caja, MATE Terminal's own dialogs, MATE Control Center) are well‑supported through Layer 2. Raw terminal content and Helix's TUI rendering rely more on Layer 1 (caret) and occasionally Layer 3 (Flat Review), which is covered in depth in the Helix chapter.

7. X11 and lightdm‑xsession Specifics

This system runs an X11 session launched through lightdm‑xsession, not Wayland. A few practical consequences follow from that:

  • Global key grabs work predictably. Orca and Marco can both register global keyboard shortcuts (CapsLock combinations, Alt+Tab, Ctrl+Alt+arrows) without the sandboxing restrictions that Wayland compositors sometimes impose on accessibility tools. You should not expect any of the shortcuts in this manual to silently fail to register because of session‑type restrictions.
  • Flat Review's screen‑reading model matches X11's rendering model. Flat Review works well on X11 because Orca can reliably inspect the text and accessibility information exposed by applications. This generally provides a consistent review experience across traditional X11 applications. This is fast and consistent on X11; behavior can differ under Wayland with different compositors, which is one reason this manual does not attempt to also cover a Wayland session.
  • lightdm is only relevant at login. Once you are inside the MATE session, lightdm is out of the picture. If Orca ever needs restarting, note that restarting Orca does not require restarting the X session or logging out — Orca can be relaunched independently.

8. Real Workflow Example — Editing Rust Code in Helix

This example ties all three layers together in a realistic sequence:

Normal work (Layer 1):

Use arrow keys and Ctrl+Arrow keys to move through code. Orca reads what you move over, character by character or word by word depending on verbosity.

Something strange appears (garbled output, a rendering glitch, unclear TUI state):

  1. Turn on Flat Review: CapsLock + P.
  2. Explore with CapsLock + I (current line) and CapsLock + K (current word) to figure out what's actually on screen.
  3. Once you've found the spot you need, sync the caret: CapsLock + 7.
  4. Turn Flat Review back off: CapsLock + P.
  5. Continue editing normally in Layer 1.

The Master Orca Rules

  1. Think in three independent positions: System Caret, Accessibility Focus, and Flat Review.
  2. The caret is for reading and editing text; arrow keys usually move it.
  3. Focus identifies the active UI control and is commonly moved with Tab, Shift+Tab, menus, and other navigation keys.
  4. Flat Review is Orca's virtual reading cursor for inspecting on‑screen content without affecting the application.
  5. Moving Flat Review does not move the real caret.
  6. You can use CapsLock + 7 to try to move the system caret to the current Flat Review position when the application supports it.
  7. As a programmer, you'll typically spend most of your time using the caret, use focus for dialogs and interface navigation, and use Flat Review as an occasional inspection or recovery tool.
  8. On Linux, AT‑SPI2 exposes the accessibility tree for applications, allowing Orca to navigate widgets, controls, and document structure.
  9. Terminal applications and TUIs such as Helix expose far less widget structure than native GUI applications, so Orca relies mainly on caret navigation, with Flat Review available when needed.
  10. On an X11 session (such as your Debian 13.6 MATE setup using lightdm‑xsession), Orca's global keyboard shortcuts are generally reliable, though accessibility ultimately depends on what each application exposes.

The Orca Debugging Mantra

When Orca does something unexpected, don't think "Why is Orca broken?" Think:

  • Which layer am I using right now?
  • Am I in Caret mode or Review mode?
  • Is this a UI element (Focus) or raw text content (Caret/Review)?
  • Is my cursor synced to where I think it is?
  • Do I need to move the caret or the focus?
  • Is Flat Review turned on when I don't actually need it?
  • Is this an AT‑SPI2 gap — is the application actually exposing accessibility info at all?
