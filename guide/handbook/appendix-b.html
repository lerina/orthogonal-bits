Appendix B: Answers and Solutions (Online)

Welcome to Appendix B!

Throughout this handbook, each chapter has ended with a set of review questions and, in most cases, hands-on assignments designed to reinforce the concepts you’ve just learned. This appendix is the companion that provides the answers and solutions to those exercises.

About this appendix

Learning Rust is an active process, and the exercises in this book were designed with that in mind. Whether you are a self-taught developer working through the book on your own, part of a study group, or a student in a classroom setting, having access to reference solutions can be incredibly helpful. This appendix is intended to serve that purpose.

Before we go further, a small but important note:

Try to solve the exercises yourself before checking the answers. The most valuable part of an exercise is not the final code snippet, but the process of reasoning through the problem and wrestling with the compiler. There is a real difference between reading a solution and understanding a solution, and that difference almost always comes from having attempted the problem first, even if you did not succeed.

If you do find yourself stuck, treat the answers here as a guide rather than a destination. Compare your approach with the one shown, and ask yourself what you might have missed. This is where the deepest learning happens.

What you will find in this appendix

This appendix mirrors the structure of the book. For each chapter that contained review questions or assignments, you will find:

  • Chapter summaries of the exercises: A brief reminder of what each question or assignment asked, so you don’t have to flip back and forth.
  • Answer explanations: For conceptual questions, the answers include not just a short response but a brief explanation of the reasoning behind it, connecting back to the material covered in the chapter.
  • Complete solution code: For programming assignments, full code listings are provided, complete with explanatory comments. Where relevant, alternative solutions are also shown, so you can see that there is often more than one idiomatic way to solve a problem in Rust.
  • Notes on common mistakes: Many solutions include a short note about the pitfalls that readers often encounter while attempting that particular exercise, along with how to avoid them.

An example of what to expect

To give you a flavor of the depth offered in the full online appendix, here is an abbreviated example: the solution to the first question from Chapter 1, along with a partial answer to Assignment 2.2 from Chapter 2.

Example: Chapter 1, Question 1

Question: “What key features of Rust make it stand out among other programming languages?”

Answer: Rust stands out primarily because of the combination of performance, memory safety, and concurrency, all achieved without a garbage collector. The most distinctive features are:

  • Ownership and borrowing: Rust’s compile-time ownership model eliminates many classes of memory bugs (use-after-free, double free, dangling pointers) that plague C and C++. Every value has a single owner, and ownership can be moved or borrowed via references. This is enforced by the borrow checker, which guarantees that references are always valid.
  • Zero-cost abstractions: High-level constructs such as iterators, closures, and generics compile down to code that is as efficient as hand-written C, so you don’t pay a runtime penalty for abstraction.
  • Fearless concurrency: The same ownership rules apply to threads. The Send and Sync traits, checked at compile time, ensure that data races cannot occur in safe Rust. This makes concurrent and parallel code dramatically safer than in most languages.
  • Pattern matching and enums with data: Rust’s match expression and its data-carrying enums (such as Option and Result) make it possible to express complex state and error handling cleanly, with the compiler verifying exhaustiveness.
  • Excellent tooling: Cargo, Rustup, and rustfmt provide a first-class developer experience out of the box, something that many systems languages lack.

Together, these features make Rust well suited to a very wide range of applications, from operating systems and embedded devices to command-line tools and web services.

Example: Chapter 2, Assignment 2.2 (partial)

Assignment: “Create a struct to represent a rectangle with width and height. Implement a method to calculate the area of the rectangle.”

Solution:

#[derive(Debug)]
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    /// Computes and returns the area of the rectangle.
    fn area(&self) -> f64 {
        self.width * self.height
    }
}

fn main() {
    let rect = Rectangle { width: 8.5, height: 4.0 };
    println!("The rectangle is {:#?}", rect);
    println!("Its area is {:.2} square units.", rect.area());
}

Notes on the solution:

  • We use f64 for width and height, which gives us the ability to represent decimal dimensions. If only whole-number dimensions were needed, u32 would work just as well and would let us derive Copy.
  • The area method takes &self because it only needs to read the fields. It does not mutate the rectangle, so a mutable borrow would be overly restrictive.
  • We derive Debug so we can print the struct with {:#?}. This is a small but useful habit for development and debugging.
  • The method returns f64 directly; there is no need to use return, since Rust treats the last expression in a block as its return value.

In the full appendix, this same assignment is accompanied by a second variant that uses u32 fields and a discussion of when each numeric type is preferable.

How to use this appendix effectively

A few brief recommendations:

  • Attempt every exercise first. Even a rough, incomplete attempt will make the answer far more meaningful.
  • Compare, don’t just copy. Compare your solution with the one given. Ask yourself what each does differently, and whether one might be more idiomatic or more efficient.
  • Try the alternatives. Where the appendix presents more than one solution, try implementing both. Exploring alternative designs is one of the best ways to deepen your Rust skills.
  • Revisit later. A question that seemed trivial early in your journey may reveal new depth once you have more experience. Don’t hesitate to come back to the appendix after you’ve finished more chapters.

A final word

Learning Rust is a journey, and the exercises in this book are the stepping stones along the path. If you have worked through them, you have already come much further than most readers of any programming book typically do. Take a moment to be proud of that.

Whether you aced every exercise or struggled through them, the important thing is that you kept going. That determination is what turns a curious reader into a competent Rust programmer.

We wish you the very best as you continue your Rust journey. Now, go build something wonderful!
